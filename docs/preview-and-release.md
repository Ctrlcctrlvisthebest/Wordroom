## 预览中新增的行为

- **本机进度**：自动记住当前词库、星标、随机顺序、位置、翻面、复习范围和造句草稿。导入/改映射/加星才重写词库；翻页和打字只保存练习状态。数据留在当前浏览器的 IndexedDB，不自动上传，也不包含同步码。清理浏览器数据会清除这些进度。
- **安全恢复**：同一浏览器两页同时练习时，发现较新存档会暂停本页保存，避免静默覆盖。读取损坏、容量不足、启动读取期间已开始新操作都会明确提示并保留当前练习；失败状态可重试。取消“本机记住进度”会清除本机副本，不清除正在练习的内容或云端副本。
- **复习范围**：卡片和抽词都可按全部 CSV、单份 CSV、仅星标筛选，文件与星标可组合。切换范围保留造句草稿；空范围不能翻页或抽词。未添加第 3 项的新导入流程。
- **云端状态**：区分已连接、尚未保存、有修改、已确认保存及结果待核对。云端仍然需要主动点击保存，不是自动/实时同步；造句草稿不上传。请求超时先读取核对，再允许手动重试；切换词库时不把新词库写进旧保存目标。包含“联想”的保存会读取核对，旧后端丢弃映射时不声称完整成功。
- **多页云端边界**：已有待核对记录不会被另一页静默替换/清除；这不是分布式锁或实时协同。未确认保存可能保守地阻止后续保存，需要先核对结果或明确打开对应云端词表。
- **音乐轻量版**：从原始音源重新生成 AAC 112 kbps / 32 kHz 连续混音，18 首、约 53 分钟、3 秒衔接不变。新文件 45,905,976 字节，旧版 65,345,724 字节，体积减少约 29.75%。18 首音源和旧版混音保留，不覆盖。网页没有新增音质切换控件；如需要可回滚资源引用，生成器也支持 `--bitrate 160`。默认仍不播放，点击前不请求音频。

本机存档不是永久备份；重要 CSV 和同步码仍需自行留存。`4174` 与线上源互相隔离，不会自动取得线上浏览器中的词库或同步码。

## 发布前检查（无远程写入）

在预览目录执行：

```sh
npm run verify:static
git diff --check
npm run benchmark:verify
```

`verify:static` 包含：

1. 检查 `index.html` 可达的本地静态资源、CSS 资源、字面量模块导入、播放列表音频以及懒加载主题文件是否存在。
2. 检查浏览器同一模块是否同时用了不同查询版本号，以及会破坏 `/Wordroom/` 子路径的根路径引用。检查器不请求外网，不是通用 JavaScript/HTML 解析器，动态拼接 URL 仍需浏览器测试。
3. 执行 Node 单元测试与 Miniflare 本地 API 测试，包括字段复选框、中英西翻译、CSV 映射和云端快照的共用契约、旧快照兼容。
4. TypeScript 无输出检查和 lint。

`benchmark:verify` 从原性能基线 Git 提交读取旧解析器做差异检查，需要保留本地 Git 历史。增加的可选字段只有在未映射且值确实为空时才从旧契约比较中排除；原有字段内容仍逐项比较。`npm run benchmark` 另外打印 Node 数据处理时延，仅供同机参考，不代表网页首屏速度或真实交互性能。

`docs/ci/validate.yml.example` 保留可选的只读权限验证工作流模板，没有 deploy、push、密钥或线上 smoke test 步骤。当前上传凭证没有 workflow 写权限，因此本次不启用新 Actions 工作流，本地发布检查照常运行。获得用户授权及所需权限后，可将模板放入 `.github/workflows/validate.yml`。它本身不会改变 GitHub Pages 的既有发布设置，也不能代替仓库分支保护。

## 不满意时如何回档

本机最简单的回退方式：关闭 `4174` 预览，继续使用原目录；原目录没有被覆盖。线上版发布后若需要回退，应以 `backup/github-before-optimization-2026-09-27` 为旧线上基线，创建恢复提交并重新发布，不能仅关闭预览。

需要从标签重建一份旧版时，可在预览仓库下执行下面的命令，**目标目录必须尚不存在**：

```sh
git worktree add --detach /Users/zoeli/Desktop/wordroom-before-optimization backup/pre-optimization-2026-09-27
```

它会创建独立的旧版副本，不改变当前分支，不删除预览代码或浏览器数据。副本需正常安装依赖后启动，或按项目已有方式复用依赖。

如果未来已经正式发布，再由用户选定需要撤销的优化提交，使用新的 `git revert` 提交恢复，并重新运行检查/发布；不要 `reset --hard`、强推或清空本地存储。回滚前端时优先保留仍兼容旧快照的新版后端，避免把保存过的联想映射再次丢弃。词表数据、草稿与服务器记录不是 Git 代码标签的一部分，发布前须保留所需 CSV 导出与同步码，回档也不应删除它们。
