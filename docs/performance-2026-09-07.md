# Wordroom 性能优化记录

## 范围

优化 GitHub 静态版的数据处理与翻卡路径。保留 UI、三语、CSV 校验规则、原始内容导出、星标及造句行为；没有新增依赖、后端或构建步骤。共享的 `parseCSV` / `createWords` 导出接口不变，React 版仍可构建。

- CSV 不再逐字符拼接字符串，改为定位分隔符后按单元格截取；引号内使用原生查找，只有存在转义引号时才替换。
- 导入和列映射校验复用已经生成的单词数组，不再重复生成。
- 空单词行提前跳过，不构造无用对象、不处理其可选字段。
- 没有星标或只改变可选字段时，不再构造全词表身份对照表来过滤星标。
- 卡片正面不再提前转义、拼接未显示的释义和长例句；翻面时才生成答案。

## 可复现基准

在仓库根目录运行 `node scripts/benchmark-wordroom.mjs`。默认对比优化前版本 `6ed193865e4be586b2bc100aedba3390d8ef22ea`，也可传入其他 Git ref。需要本地有对应 Git 历史，不需要联网或安装额外包。

环境：macOS / arm64，Node v24.18.1；每项预热 6 轮、正式测量 20 轮，交替新旧执行顺序，报告中位数。数据为合成 CSV，不是用户私人词表。每条数据含单词、释义、长例句和搭配。

下表记录第二次完整运行的“解析 + 单词整理”耗时。旧流程包含两次映射，新流程一次；两者返回的数据一致。

| 合成词表 | 字节数 | 优化前 | 优化后 |
| --- | ---: | ---: | ---: |
| 2,000 词，普通长例句 | 441,807 | 6.024 ms | 0.623 ms |
| 20,000 词，普通长例句 | 4,457,807 | 106.482 ms | 7.249 ms |
| 20,000 词，带转义引号及换行 | 4,157,807 | 90.463 ms | 11.166 ms |

两次完整运行中，20,000 词普通词表该路径分别为 114.244 → 6.654 ms、106.482 → 7.249 ms；带引号及换行词表分别为 90.139 → 10.265 ms、90.463 → 11.166 ms。

这些不是浏览器性能指标：不包含读文件、字段自动识别、DOM 渲染、网络或首次加载，也不代表整个网站同倍数变快。机器负载、垃圾回收与浏览器引擎会影响实际耗时。单独解析与解析后整理为独立测量，不能相减推导映射耗时。本次未配置 Chrome 性能工具，没有声称测得 LCP / INP / CLS。

## 验证

- 48 项自动化测试全部通过；页面交互由最小 DOM 模拟验证，不是浏览器布局测试。
- 基准脚本穷举字母、空格、逗号、双引号、CR、LF 组成的长度 0–5 输入：9,331 组新旧结果或错误消息完全一致；另对三份大词表比较完整解析和映射结果。
- 新增边界覆盖：尾随分隔符、连续引号、混合换行、长例句、密集转义引号、空词跳过、映射只执行一次、更换单词列后的星标身份匹配。
- 既有测试继续覆盖 5 MB / 20,000 行 / 100 列限制、错误导入回滚、异步导入竞争、三语、星标完整 CSV 导出、分页及造句保留。
- `npm test`、`npm run lint`、`npm run lint:wordroom`、`tsc --noEmit`、`npm run build`、`git diff --check` 均通过。

暂不引入 Worker 或打包压缩链：先消除已测到的计算和分配开销，保持静态版部署方式与依赖不变。如果真实移动设备仍出现大文件导入卡顿，再进行浏览器性能采样后决定是否转到后台线程。
