# Wordroom GitHub 版代码检查（2026-09-07）

## 范围

检查 GitHub Pages 的 `index.html`、`wordroom.js`、样式引用、类型声明及自动化测试，并检查共享工具在 React 入口中的使用情况。遵循项目现有 Sites 规范保留页面架构、依赖和样式；本次只发布 GitHub Pages，不部署 ChatGPT 站点、不重打离线包。

## 已修复的问题

- 连续导入存在异步竞争：加入请求序号，过时读取的成功或失败均不再覆盖后一次选择。
- 空词列等失败导入原先会替换词库：改为完整校验后再提交状态；失败时保留旧词库、星标、卡片和造句。
- CSV 解析原先会静默吞掉错误引号并裁剪原始空格：现在明确校验引号；学习时仍清理空格，导出保留原始单元格内容。允许缺少末尾可选值，拒绝数据列多于表头的行。
- 模糊列名匹配可能把 `password` 当作单词列：优先匹配完整列名，英文模糊匹配以词为单位。无已知单词列名时优先使用有内容且未被其他字段占用的列；明确命名但为空的单词列仍报错。重复表头加列号以便区分。
- 可选字段修改原先会重洗牌并清空练习：现在保留当前顺序、位置、抽词和造句。非法、重复、空单词列映射不会提交。改变单词列本身仍会开始新练习，避免给新词误用旧答案。
- 星标和视图切换原先重建整个抽词列表：星标改为原位更新，并移除仅切换视图时的重建，保留输入节点和选区。
- 大批抽词原先创建全部输入框：改为每页 12 项，保留用户选择的总抽词数和跨页答案。
- 解析结构没有上限：保留 5 MB 限制，增加最多 20,000 数据行、100 列的解析中检查。
- 数量处理原先把科学计数法 `1e2` 解析成 1：改为数值解析、有限值检查及整数截断；初始化示例词表也同步输入上限。
- 翻译替换中的 `$&` 等内容会被当作替换指令：改为单次回调替换，变量按字面插入；不读取语言字典的继承属性。
- 下载异常原先会直接抛出：增加错误提示与清理逻辑，延迟回收临时下载 URL，保留星标以便重试。

## 去重与清理

- 删除无引用的 `LABELS` 常量及其类型声明。
- `OPTIONAL_FIELDS` 从 `FIELDS` 推导，避免维护两份字段清单。
- 删除 GitHub 页内与 `headers` 完全重复的 `sourceHeaders` 状态。
- 映射对象作为字段启用状态的唯一来源，复选框由它同步，不再从复选框反向推断状态。
- 合并卡片重洗牌、控制器同步和星标按钮状态更新逻辑；移除重复渲染和清空操作。
- 保留分别服务 GitHub Pages 和 ChatGPT 站点的两个渲染入口，不将仍在使用的入口、依赖或组件库误删为遗留代码。

## 验证边界

交互回归使用执行实际页面脚本的轻量 DOM 模拟，不等同于真机浏览器、输入法、下载兼容性或视觉测试；没有声称排除所有潜在问题。页面仍是会话内词库，刷新会丢失本次词库和练习，未擅自新增持久化。

星标导出保留单元格值而非原 CSV 的引号样式或记录换行形式。为满足原始内容导出要求，不自动改写以等号等字符开头的单元格；打开不可信 CSV 时应在表格软件中按文本导入，避免执行其中的公式。
